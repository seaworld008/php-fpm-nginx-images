# 9. 给 Codex / 工程执行者的实施任务书

> **执行方式：** 完整阅读 README 与本文件；有 superpowers 时按 executing-plans 或 subagent-driven-development 逐项执行，没有插件也保留测试和证据门禁。不要只重新输出方案。
>
> **Goal：** 保留 PHP 7.2.34 和既有应用接口，交付可审计的 Nginx/PHP-FPM 镜像与本机修复流程；不把框架迁移混入应急任务。
>
> **Architecture：** 容器采用干净 Bookworm + 已核验同源回移 + Nginx stable；本机按包管理/源码/面板分流。共享证据、扩展和验收规范，分别验证制品。
>
> **Tech stack：** PHP 7.2 NTS、Nginx stable、Linux、BuildKit、Jenkins、Kubernetes；工具为 Python 3.8+ 标准库。
>
> **Spec：** [容器](02-container-build-plan.md)、[本机包管理](03-native-package-repair.md)、[本机源码](04-native-source-repair.md)、[运行时](05-runtime-and-performance.md)。

## 全局约束

仅访问明确授权的本地/SSH 环境；不猜地址、不关闭 host-key 校验、不索要明文密钥。默认仅构建和隔离验证，不升级生产包、不重启服务、不改宿主机源/sysctl/daemon、不覆盖旧 tag、不删除镜像/数据、不自动采购。

不修改应用框架大版本或数据库结构。没有可信 PHP 7.2 补丁不自动换成 PHP 8。允许继续可独立完成的任务，但必须记录阻塞，禁止伪造通过。

## 审查重点

1. 版本仍是 7.2.34 时的供应商修订与真实补丁覆盖。
2. CLI/FPM 配置不同及扩展 ABI/序列化差异。
3. 多进程信号、忙时探针和所有旧进程是否退出。
4. 本机包事务、前缀、面板覆盖和绝对路径调用。
5. 密钥、签名、公开许可和生产操作权限边界。

## 任务 1：现场清单与授权核对

产物：受限 inventory、脱敏摘要、授权范围表。

- [ ] 读取实际 OS/架构、PHP 来源、FPM 路径、资源和部署方式。
- [ ] 记录扩展具体版本、真实路由/配置/上传/Session、CLI worker/cron。
- [ ] 按容器或本机路线分流；不把仓库例子当现场事实。
- [ ] 验证输出无公开密钥；失败/不可读字段写明，不猜。

## 任务 2：补丁和版本锁

产物：逐 CVE evidence、versions/packages/extensions 锁、来源归档。

- [ ] 再核对官方公告、维护者候选与 Nginx stable。
- [ ] 取得匹配源包、补丁、签名元数据与包 hash；明确完整/最小回移。
- [ ] 编写拒绝缺字段、假 hash、跨 PHP 主版本和混源的测试，再实现锁校验。
- [ ] 只有证据一致时提升状态；未验证不标 fixed。

## 任务 3：干净镜像构建

产物：container/Dockerfile、分层构建、锁消费和清单。

- [ ] 先写构建契约测试：PHP 必须 7.2.34、扩展 ABI 一致、不能含秘密/开发工具。
- [ ] 生成固定 digest/包版本的 builder/runtime；不从旧业务镜像派生。
- [ ] 实际构建并保存退出码、日志、ID；没有 Docker 环境就标阻塞。

## 任务 4：扩展兼容

产物：web/worker/full-compat 映射与测试。

- [ ] 以需求档案和现场差异建立失败用例，再安装锁定扩展。
- [ ] 验证 MongoDB、Swoole、Redis/igbinary、memcached 等 API 和测试数据。
- [ ] 修正重复加载；冲突时解释派生镜像拆分，不删除必要模块蒙混。

## 任务 5：Nginx 路由与安全

产物：配置模板、专用 FastCGI include、路由测试。

- [ ] 先记录旧路由对照；覆盖 query/重复 s/中文/入口/PATH_INFO。
- [ ] 固定执行入口、拒绝上传 PHP/隐藏/备份/管理路径；测试 location 优先级。
- [ ] 确认 HTTPS/代理链、上传和日志行为；配置检测通过再做请求测试。

## 任务 6：FPM/OPcache 与模板

产物：参数白名单、配置渲染器、资源 profile。

- [ ] 先测非法数值、无 limits、cgroup 差异、动态池约束和挂载代码场景。
- [ ] 不对全部文件无参数 envsubst，不使用 eval，不引入 PHP 8 专属项。
- [ ] CLI 和真实 FPM 请求分别核验；参数以压测而非猜测决定。

## 任务 7：生命周期与探针

产物：entrypoint、监督器、drain、healthcheck 和故障测试。

- [ ] 先写 master 意外退出、启动失败、TERM/QUIT 和繁忙池用例。
- [ ] 实现有界启动、关键进程失败联动和有序排空；禁止 tail 保活。
- [ ] 验证 loopback 管理端口与 exec probe 一致，无重启风暴。

## 任务 8：Jenkins/Docker/K8s

产物：ci 和 deploy 目录、业务镜像样例、密钥接入说明。

- [ ] 基础镜像 digest 与业务层分离；Composer 锁/插件/脚本审计。
- [ ] 配置通过受控挂载，私有依赖通过构建 secret，不 COPY 密钥。
- [ ] 解析 Compose/YAML，真实环境 dry-run 后做隔离验证；默认不 apply 生产。

## 任务 9：本机包管理方案实证

产物：发行版矩阵、受审查事务、升级/回退演练。

- [ ] 在克隆机确认完整包族、签名、源包与依赖，不仅更新 CLI。
- [ ] 先模拟事务并保存旧制品/配置，再在授权测试机执行。
- [ ] 验证自动重启/INI/alternatives 影响及 FPM、队列、cron 全部更新。

## 任务 10：本机源码/面板方案实证

产物：补丁来源、构建脚本、独立 prefix 制品、候选 service 和切流脚本。

- [ ] 先写前缀隔离/错 ABI/错来源拒绝测试；没有补丁不得编原版冒充修复。
- [ ] 在同平台构建，独立 INI/扩展/socket/pid；验证暂存安装无系统覆盖。
- [ ] 测试并行 FPM、Nginx 切流、CLI 绝对路径和回滚；面板需遵守其管理边界。

## 任务 11：完整验收与压测

产物：validation、performance、残余风险、原始证据。

- [ ] 执行来源、配置、FPM、扩展、路由、业务、信号及回滚矩阵。
- [ ] 仅隔离环境运行经审核回归；不执行公网/生产攻击测试。
- [ ] 同资源压测并算后端预算；未测项不打勾，不能用 echo QPS 代表业务。

## 任务 12：审查与交付

产物：制品、锁、报告、SBOM、校验、许可、操作手册。

- [ ] 自审所有结论与证据一致，敏感内容不进入 Git/镜像层。
- [ ] 运行仓库检查及新增测试，记录实际结果。
- [ ] 默认只交付候选；公开制品和生产发布需对应授权与门禁。
- [ ] 提交普通 commit/PR，保持历史，不强推、不删除旧 release/tag。

## 最终报告必须回答

实际做了什么；镜像/本机制品是否构建/验证/推送/部署；每个 CVE 的状态；完整包修订与 hash；扩展/业务/压测范围；残余风险；阻塞；回滚方法；下一步最小必要操作。

不能把“已写方案”“已构建”“已打补丁”“已上线”混为一项完成状态。
