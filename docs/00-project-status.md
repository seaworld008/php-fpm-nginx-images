# 0. 状态、范围与如何使用

更新时间：2026-10-22。

这是公开的修复工程方案与审计工具仓库，当前交付不是可直接执行的镜像构建系统，也不是一键热补丁程序。不要在生产下载仓库后直接执行未审核命令。

## 已有与未有

已有：容器、本机包管理、本机源码/面板的实施步骤；高并发、Jenkins/K8s、扩展、测试与回滚规范；最小清单工具；证据与验收模板。

未有：核验闭环的 PHP 7.2 目标包；可复现 Dockerfile；经过运行测试的进程监督/探针实现；业务压测；发布的镜像/安装包。工具和文档测试不替代这些工作。

## 设计范围

初始容器设计选择 Debian 12 Bookworm，目的是减少原有 Debian 12 系运行时的迁移变量，不代表 Bookworm 是最新 Debian，也不代表第三方 PHP 7.2 包享有 Debian 官方安全承诺。其他发行版按对应本机路线独立验证。

语言目标为 PHP 7.2.34 NTS。现有 7.2.0—7.2.33 要同时验证小版本累积行为变化。PHP 7.2.34 原版也不能直接当修复包。

兼容接口设计：端口 80；应用目录 `/usr/share/nginx/html`；公开入口 `public/`；FPM socket `/run/php/php7.2-fpm.sock`。用户名/UID、时区、内存和上传大小按实际应用明确配置，不强制覆盖现有值。

这次不迁移框架、不改数据库结构、不改 CNI、不改业务为 Swoole 模式，不把所有扩展或所有进程强塞进一个服务。

## 发布状态必须拆开

1. 源码/包来源已验证。
2. 每个 CVE 的补丁证据已核对。
3. 镜像/本机制品已构建。
4. CLI 与真实 FPM 路径已验证。
5. 业务与扩展已回归。
6. 压测与故障/回滚已验证。
7. 获得授权并已部署。

上一步成功不自动推出下一步。没有源码、测试账号或环境时，写明阻塞，不用模拟页面冒充业务验收。
